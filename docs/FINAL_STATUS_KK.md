### Аудит кезінде табылып, түзетілген ақаулар (7)

1. Fixture режимі SSRF жеке-IP тексеруін толық айналып өтетін → тек loopback рұқсат етілетін болды.
2. Тапсырма іздеу «тест» кілт сөзімен «жеңілу» батырмасын кездейсоқ басатын → кілт сөз нақтыланды.
3. Ашық модаль терезе кейінгі батырма әрекеттерін бұғаттайтын → модаль тазалау қосылды.
4. XSS-зонд тек бірінші өрісті тексеріп, керек батырманы баспайтын → 3 өріс + барлық «жіберу» батырмалары.
5. Қайта тексеруді дубликат терезесі бұғаттайтын → `isRetest` жалаушасы.
6. Есептер «completed» күйінен кейін дайындалып, клиент жартылай жазба алатын → реті ауыстырылды.
7. E2E қайта іске қосқанда дубликат терезесі кедергі жасады → e2e ортасында терезе өшірілді (белсенді дубликат бәрібір бұғатталады).

## 4. Адал шектеулер (не тексерілмеді)

- **Нақты студент жобалары тексерілмеді** — тек басқарылатын fixture. Нақты жобаларда эвристика (кілт сөздер, canvas) басқаша нәтиже беруі мүмкін.
- **Firebase/Firestore**: конфигурация және қауіпсіздік ережелері дайын, бірақ нақты Firebase жобасы болмағандықтан **іске қосылып тексерілмеді**.
- **Google OAuth**: дәл солай — нақты клиенттік тіркелгісіз тестіленбеген. Аудиттелетін сайттардағы Google кіруі тек «батырма бар» деңгейінде дәлелденеді (нақты кіру — тесттік аккаунт қажет).
- **Canvas ішкі күйі** сырттан көрінбейді — механика толық дәлелденбесе «Ішінара» қойылады.
- **Өмірді автоматты таусу** нақты ойындарда мүмкін емес — «жан біткенде» толық ағыны тек арнайы батырмасы бар жерде ғана PASS алады.
- **Тарихи дәлдік** жауаптар кілтінсіз автоматты расталмайды («Алдын ала АИ бағалауы» + оқытушы тексеруі).
- **Rate limiting, толық пентест** орындалмады — тек қауіпсіз, бұзбайтын бақылаулар.
- **Публичный деплой жоқ**: ортада сыртқы хостингке шығу мүмкіндігі тексерілмеді; Dockerfile + нұсқаулық дайын.
- Рейтинг деректерінің **шынымен сақталуы** аутентификациясыз дәлелденбейді (кестенің көрінуі — сақтау дәлелі емес).

## 5. Қалған баптау қадамдары (өндіріске шығару)

1. Серверді орналастыру: `docs/DEPLOY_KK.md` (Docker немесе VPS; Playwright бинарлықтары міндетті).
2. `.env`: күшті `ADMIN_TOKEN`, `ALLOW_LOCALHOST_FOR_TESTS=0`.
3. Қажет болса: Firebase жобасы + service account (ертеңгі күні дерекқорды ауыстыру), Google OAuth клиенті.
4. `data/answer_key.json` — тарихи дәлдікті автоматты тексеру үшін оқытушы бекіткен жауаптар кілтін енгізу.
5. HTTPS (кері прокси) қосу және өндірістік тексеру тізімін орындау.

## 6. Пайдалану (қысқаша)

1. `npm install && npx playwright install chromium --with-deps`
2. `cp .env.example .env` → `ADMIN_TOKEN` орнату
3. `npm run build -w client && npm run start -w server` → `http://localhost:8787`
4. Кіру → «Жаңа жобаны тексеру» → студент, топ, URL, тапсырма (A1–A6) → «Тексеруді бастау».

Сынақ режимі: `ALLOW_LOCALHOST_FOR_TESTS=1` болғанда `http://localhost:8787/fixture/` — платформаның өзін тексеруге арналған сайт (студент жобасы емес).
